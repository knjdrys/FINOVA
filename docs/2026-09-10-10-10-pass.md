## Feature gap analysis (per standing instruction: discover, don't ask)

Re-audited the full repo against modern premium personal-finance expectations
(every screen, modal, domain engine, service, and test inventory). Found and
**implemented** four important gaps:

### 1. Full backup & restore (JSON) — *was missing entirely*
The `lastBackupDate` settings field existed but nothing used it. Moving to a
new phone was impossible. Now:
- **Settings → Data → Full Backup (JSON)**: downloads a versioned,
  self-describing file with the entire state (accounts, transactions,
  categories, budgets, goals, commitments, recurring, settings).
- **Restore from Backup**: strict validation (`BackupService.parseBackup`) —
  not-JSON / wrong-app / wrong-version / malformed-shape each rejected with a
  localized message, never half-applied. Confirm dialog shows exactly what
  will be replaced. Round-trip tested: `serialize → parse` is identity.
- `lastBackupDate` is now real and displayed ("Last backup: …").

### 2. CSV transaction import — *export existed, import did not*
- **All Expenses → upload icon** (next to export). RFC-4180 parser
  (quoted fields, embedded commas/quotes/newlines).
- FINOVA's own export re-imports losslessly and is **idempotent** (IDs kept;
  re-import → 0 new, N duplicates).
- Generic bank/finance CSVs supported via header aliases (date/description/
  memo/payee, amount/value/debit/credit, type, category, account, currency).
- Date formats: ISO, MM/DD/YYYY, DD/MM/YYYY (13th-disambiguated), 2-digit
  years. Currency-symbol stripping (₱, $, PHP…). Foreign-currency rows are
  skipped, never mixed into the single-currency ledger.
- Unmatched categories land in auto-created **Other / Other Income**.
- Preview modal: ready / duplicates / problem-rows counts, row samples,
  per-line error reasons. Nothing applies until confirmed. Imported rows
  apply to account balances through the same engine as manual adds.

### 3. Undo for destructive actions — *deletes were permanent*
- 6-second **Undo snackbar** (fixed, above the nav) for:
  - Transaction delete (snapshot of ledger + balances restored)
  - Start Fresh (full state snapshot restored)
- Cloud users: undo re-enqueues a full state sync (queued after the pending
  delete op, so the ledger converges back).

### 4. Subscription intelligence — *recurring drain invisible*
- **Insights → Subscriptions card**: N active subscriptions, combined
  monthly cost, each with next due date, and "Next charge: …".
- Demo data now seeds 3 subscriptions (Globe Home Fiber, Netflix, Spotify)
  so the card is alive on first run.
